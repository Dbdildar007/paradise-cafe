# Fix: UnsatisfiedLinkError - library "libhermes_executor.so" not found

Cause: the installed APK has no (or mismatched) Hermes native library. Usual reasons, most likely first:
1. android/ was generated by a different React Native version than package.json (0.76.5).
2. Hermes flag mismatch / stale build cache / old APK still installed.
3. Wrong CPU ABI (APK has x86_64 only, phone is arm64-v8a).
4. Release only: `extractNativeLibs=false` or aggressive R8 rules (removed in this repo's native-config).

## Steps
```bash
# 0. Versions must match
node -p "require('./node_modules/react-native/package.json').version"   # 0.76.5
# 1. android/gradle.properties must contain
#    hermesEnabled=true
#    newArchEnabled=true
#    reactNativeArchitectures=armeabi-v7a,arm64-v8a,x86,x86_64
# 2. android/app/build.gradle must have (RN 0.76 template)
#    react { autolinkLibrariesWithApp() }   and   implementation("com.facebook.react:react-android")
#    implementation("com.facebook.react:hermes-android")
# 3. AndroidManifest.xml: delete android:extractNativeLibs="false" if present
# 4. Clean everything and reinstall
adb uninstall in.paradisecafe.app
rm -rf node_modules android/.gradle android/build android/app/build
npm install
cd android && ./gradlew clean && cd ..
npx react-native start --reset-cache      # terminal 1
npm run android                            # terminal 2
# 5. Verify the library really is in the APK
unzip -l android/app/build/outputs/apk/debug/app-debug.apk | grep -E "hermes|libreactnative"
adb shell getprop ro.product.cpu.abi      # your phone's ABI must appear in that list
```
If the unzip shows no `libhermes*.so` for your ABI, regenerate android/ with the matching version:
`npx @react-native-community/cli@15 init Tmp --version 0.76.5` and copy its `android/` over, re-applying
`native-config/android` changes (package name, signing, manifest, proguard).

## Root cause found (and why this repo now ships android/ + ios/)
The trace `ReactNativeHost.createReactInstanceManager -> getDefaultJSExecutorFactory -> HermesExecutor` happens when
`MainApplication` does not set `isHermesEnabled` / `isNewArchEnabled` / call `load()` consistently with `gradle.properties`
(`newArchEnabled=true` ships only new-architecture libs, so the legacy `libhermes_executor.so` is absent).
The android/ folder in this repo is the unmodified official 0.76.5 template (those three things are set correctly),
plus: env-based release signing, R8, backup/cleartext off, and a debug-only network config for Metro.
**Copy the whole android/ and ios/ folders from this zip over yours** - do not merge file by file.
